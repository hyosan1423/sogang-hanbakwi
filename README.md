# 서강 한 바퀴 (Sogang Hanbakwi)

서강대 주변 가게(식당·카페·술집·바)를 가격, 거리, 혼밥 가능 여부, 영업시간으로 바로 걸러 보는 모바일 웹앱입니다. 직접 방문해 모은 167곳을 담고 있으며, 스토어 설치 없이 "홈 화면에 추가"로 앱처럼 쓸 수 있습니다.

- 서비스: https://sogang-hanbakwi.web.app
- 상태: 운영 중 (2026-10-05 배포)
- 개발: 신효산 (서강대 물리학과·전자공학과), 1인 개발

이 저장소에는 **소스 코드와 빌드·테스트 도구만** 올려 두었습니다. 직접 수집한 가게 데이터와 배포 설정은 포함하지 않았습니다.

---

## 1. 데이터 흐름

```
가게 JSON (직접 수집)
      │  tools/build.py
      ▼
정적 사이트 (index.html + 가게 스냅샷 + sitemap + service worker)
      │  Firebase Hosting 배포
      ▼
사용자 브라우저 ──(변경된 가게만)──> Firestore
      │
      └─ Google 로그인 ──> users/{uid} : 계정별 즐겨찾기
```

관리자는 별도 관리 페이지에서 가게를 고치고, 고친 내용은 사용자 화면에 실시간으로 반영됩니다.

## 2. 기술 구성

| 영역 | 사용 기술 | 역할 |
|---|---|---|
| 프론트엔드 | 순수 HTML·CSS·JavaScript (프레임워크 없음) | 목록, 필터, 상세, 즐겨찾기 UI |
| 설치형 웹앱 | PWA (manifest, service worker) | 홈 화면 추가, 오프라인 캐시 |
| 인증 | Firebase Authentication (Google 로그인만) | 계정별 즐겨찾기 |
| 데이터베이스 | Cloud Firestore | 가게 수정분, 사용자 즐겨찾기 |
| 호스팅 | Firebase Hosting (무료 요금제) | 정적 파일 배포 |
| 빌드 | Python 3, esbuild | 사이트 생성, Firebase SDK 번들링 |
| 테스트 | Playwright (가짜 Firebase로 UI 검증) | 로그인, 즐겨찾기 분리, 데이터 갱신 |

## 3. 가게 데이터 구조

가게 하나는 문서 하나이며 주요 필드는 다음과 같습니다.

| 필드 | 내용 |
|---|---|
| `name`, `address`, `mapUrl` | 이름, 주소, 지도 링크(외부 지도 API 없이 링크만 연결) |
| `category` | 가성비 맛집, 적당한 맛집, 자주 갈 맛집, 카페, 술집, 바 (6종) |
| `kinds`, `food`, `features` | 음식 종류, 대표 음식, 특징 |
| `menus`, `price` | 메뉴와 가격, 대표 가격 |
| `hours` | 요일별 영업시간 문자열 (브레이크타임 포함) |
| `distanceM`, `zone`, `lat`, `lon` | 정문 기준 거리, 구역, 좌표 |
| `solo` | 혼밥 가능 여부 |
| `verifiedAt`, `updatedAt` | 마지막 확인일, 수정 시각 |

## 4. 소스 구성

| 경로 | 역할 |
|---|---|
| `src/app.src.html` | 앱 본체. 화면, 필터, 정렬, 상세, 즐겨찾기 로직이 한 파일에 있음 |
| `src/fb.js` | Firebase 연동: 로그인, 가게 변경분 구독, 즐겨찾기 저장 |
| `src/parse.js` | 영업시간 문자열을 요일별 영업·휴무·브레이크타임으로 해석 |
| `tools/build.py` | 가게 데이터를 읽어 정적 사이트, 사이트맵, robots.txt, service worker 생성 |
| `tools/bundle.mjs` | esbuild로 Firebase SDK를 한 파일로 번들링 |
| `tools/test_ui.py`, `tools/stub_fb.js` | Firebase 없이 화면 동작을 검증하는 자동 테스트와 가짜 Firebase |

## 5. 설계 결정

**① 스냅샷 + 변경분 구독.** 가게 목록 전체를 매번 Firestore에서 읽으면 무료 요금제의 읽기 한도(하루 5만 건)를 방문자 수에 비례해 소모합니다. 그래서 빌드 때 목록 스냅샷을 사이트에 포함하고, 그 이후에 고친 가게만 `updatedAt` 기준으로 받아 덮어씁니다. 삭제는 표시만 남기는 방식(tombstone)으로 처리합니다.

**② 기준 시각 고정.** 기준 시각을 빌드 시점으로 두면 재배포할 때 그 사이 관리자가 고친 내용이 화면에서 사라집니다. 기준 시각을 고정값으로 두어 어떤 순서로 재배포해도 수정분이 유지되게 했습니다.

**③ 계정별 즐겨찾기 분리.** 같은 브라우저에서 계정을 바꾸면 이전 계정의 로컬 캐시가 새 계정에 합쳐지는 문제가 있었습니다. 캐시에 소유 계정을 기록하고, 로그아웃 때 정리하며, 소유자가 다를 때는 합치지 않는 규칙으로 해결했고 자동 테스트로 재현·검증했습니다.

**④ 외부 지도 API 미사용.** 지도 서비스의 약관상 응답을 저장해 자체 데이터베이스로 쓰기 어렵기 때문에, 가게 정보는 직접 수집하고 지도는 링크로만 연결했습니다.

**⑤ 보안 규칙.** 가게 문서는 누구나 읽을 수 있고 쓰기는 관리자 계정(이메일 인증 완료)만 가능합니다. 사용자 문서는 본인만 읽고 쓸 수 있습니다.

## 6. 빌드와 배포

```
npm install
npm run build          # Firebase SDK 번들 + 정적 사이트 생성
firebase deploy --only hosting
```

가게 데이터(`data/shops/*.json`)와 Firebase 프로젝트 설정은 이 저장소에 포함되어 있지 않으므로 그대로 실행되지는 않습니다.

## 7. 미해결 항목

- 아이폰 홈 화면 앱(standalone)에서의 Google 로그인은 다른 기기에서 직접 검증하지 못했습니다.
- 보안 규칙의 거부 동작(비로그인 쓰기, 타인 문서 읽기)은 콘솔의 시뮬레이터로 확인할 예정입니다.
- 일부 가게는 영업 여부, 가격, 영업시간이 비어 있거나 출처 간에 어긋나 있습니다.
- 검색엔진(구글, 네이버) 노출은 등록 후 수집을 기다리는 중입니다.
